Methodology · v0.1

How the index is computed.

Every score is derived from a transparent set of weights, live policy data, and a Claude-generated map of project-specific exposures. The math is in data/castle_eri/index_math.py.

The four sub-scores

Each project gets four sub-scores on 0–100 (higher = more risk). The composite is the weighted sum, rounded.

Policy
35%

Bills, Treasury rules, and agency actions that change the tax credit, permitting, or domestic-content regime tied to the project.

Trade
25%

Tariffs (Section 201 / 232 / 301), AD/CVD, UFLPA enforcement — sized to imported component value × current rate × probability of escalation.

Geopolitical
25%

Supply-chain HHI by country × country risk index; export controls, sanctions, and disruption scenarios.

Macro
15%

IRR cushion against ±100 bps rate moves, weighted by time-to-COD. Material only for pre-FNTP projects.

Attention score

Each tracked risk carries an attention score (0–100) and a 12-week activity sparkline. Activity counts the number of Congress.gov bills and Federal Register notices in the live pull whose title / summary / latest action references any of the risk's keywords, bucketed by the week the action occurred.

The score is normalized so the most-mentioned risk in the portfolio reads 100; everything else is the ratio of its total mentions to that peak. Likelihood (Low / Medium / High) is a separate, judgment-based bucketing of the Claude mapper's probability estimate: < 25% Low, 25–55% Medium, ≥ 55% High.

This split mirrors a two-track approach — a quantitative what's-getting-attention-right-now signal alongside a qualitative what's-likely-to-happen assessment.

How exposures are mapped

For each project, Claude (Sonnet 4.6) is prompted with the project's technology, suppliers, location, capex, target IRR, offtake status, and policy dependencies. It returns a structured list of 6–10 specific risk factors spanning all four sub-score categories, each carrying:

  • A category (policy / trade / geopolitical / macro)
  • A specific citation — bill number, IRC section, HTS code, EO, or rule docket
  • A dollar impact, defended as a fraction of the project's capex
  • A probability of the adverse outcome over the next 18 months
  • 3–6 search keywords used to find live Kalshi markets and Congress / Federal Register items

The system prompt is cached via Anthropic prompt caching so repeat invocations across projects re-use the cached prefix. If the call fails or the SDK is unavailable, a deterministic stub maps each project's seed dependencies + suppliers into a baseline factor list — so the dashboard never goes blank.

How hedges are sized

For each factor, the data layer ranks every live Kalshi market by token overlap between the factor's keywords and the market's title / event / category. Top 3 per factor are surfaced.

Notional sizing uses the BUILD.md formula for binary YES contracts:

notional = expected_loss / (1 − YES_price)

The cost to enter is then notional × YES_price. Notional represents the number of $1-payoff shares; if the adverse event resolves YES, the payoff covers the expected loss net of premium.

Data sources

Congress.gov

Bills are pulled from the api.congress.gov/v3/bill endpoint keyed via api.data.gov, filtered to substantive bill types (no HCONRES / SCONRES adjournment resolutions), with at least one query token appearing in the bill title.

Federal Register

federalregister.gov/api/v1/documents, sorted newest, filtered by per-project keyword seed. No authentication required.

Kalshi

api.elections.kalshi.com/trade-api/v2/events?with_nested_markets=true, filtered to relevant categories (Politics, Economics, Climate and Weather, Companies, World, Commodities, Financials), then token-matched against the factor's keywords. Public read endpoints — no API key required.

Caching

Each client caches responses by request key in data/castle_eri/cache/ with TTLs: Congress 6h, Federal Register 12h, Kalshi 15m. Re-runs of refresh.py are <2s after the first run.

Limitations

This is a prototype, not investment advice. The factor probabilities and dollar impacts are Claude-generated estimates anchored against the project's actual seed data — they are explainable but not auditable. The country-risk table is static. The hedge mapping ranks markets by keyword overlap, not by historical hedge effectiveness. Kalshi markets resolve based on a specific event description, which may not match the underlying exposure exactly.
